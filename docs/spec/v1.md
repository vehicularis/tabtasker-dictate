# TabTasker Dictate 1.0: the build spec

This is the contract every builder works from. Read all of it before touching code. Where it is
silent, make the call a senior Mac product engineer would make, and say so in your report.

## 1. Intent

Can (the owner) wants this to be the best Mac dictation app there is: top-notch setup, top-notch
settings, ultimate customization, best-in-class design and UX, and first-class Claude agent
integration. His words: "do not do mistakes, make it super professional". The bar is Apple's own
apps and the best of Wispr Flow, Superwhisper and Granola, with everything running on the Mac.

**Anti-goals** (a failure even if it works):
- Anything that sends speech off the Mac without the person turning that on. Whisper runs locally.
  Claude features are opt-in and send only text.
- A look of its own. Dictate is part of the TabTasker family and uses TabTasker Business's design
  system (section 6): its fonts, surfaces, elevation and one blue accent. Red is allowed only for a
  destructive action or an error, green only for a state that is fine. No gradients for decoration,
  no sparkles, no emoji in the UI.
- Settings that do nothing, controls that lie, placeholder pages, "coming soon".
- A setting that needs a restart, unless it says so.
- Losing what someone said. Every path that can fail keeps the words.

## 2. Ground rules for builders

These come before any feature:

- **Do not launch the app.** That means no `tauri dev` and no `open` of a built `.app`. The owner's
  copy is running and listening for fn, and only the lead launches builds. Check UI in a browser
  through the Vite dev server and the browser mock (section 5.4).
- **Never post synthetic keyboard or mouse events** to the system (CGEventPost) from tests or
  scripts, and never move the owner's mouse or type into his apps.
- **Never change macOS privacy (TCC) or system settings**, other apps' defaults, `~/.claude*`,
  Claude Desktop's config or the real `claude mcp` registry. Test installers against a temporary
  HOME.
- **Never call the Anthropic API or the `claude` CLI for real.** There is no key. Use unit tests
  with canned responses.
- **Never read, write or delete** the owner's real notes in `~/Documents/TabTasker Dictate` or the
  real app data in `~/Library/Application Support/com.tabtasker.dictate`. Tests use temp dirs.
- **Kill only processes you started**, such as your own Vite server on your assigned port.
- **Git:** work only in your assigned worktree and branch. Commit with the configured identity
  (acanturgut <acanturgut@outlook.com>) and end every message with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push, add a remote or create a
  GitHub repo.
- **Dependencies:** none unless the platform truly can't do it. A new crate or npm package must be
  MIT, Apache-2.0, BSD, ISC or Zlib licensed (never GPL or LGPL), pinned to an exact version, and
  at least 14 days old. Prefer a few lines of Objective-C over a crate: AppKit, CoreAudio,
  Security and ScreenCaptureKit are all available.
- **Code comments:** only what the code cannot say (the why, an invariant, a gotcha), short, in
  present tense. Never cite tickets, plans, specs, reviews or history. Match the surrounding idiom:
  two-space indent, terse Rust, ObjC in the existing `TTVoice` style, React function components,
  plain CSS.
- **Copy:** sentence case, short, plain words. No em or en dashes in UI text. Say what happens
  ("Saved to Notes"), not what the code does.
- **Accessibility:** every control is reachable by keyboard, has a visible focus ring in the accent,
  and a real label. Respect reduced motion. Check light and dark.
- **Verify before you claim.** Every builder runs, and reports the output of:
  - `npm run build` (tsc and vite);
  - `cargo test --manifest-path src-tauri/Cargo.toml` (debug);
  - `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` if clippy is
    installed (otherwise `cargo check --all-targets` with no new warnings);
  - a browser pass of every screen you touched, in light and dark, with screenshots.

## 4. The settings store (foundation)

The store lives in `~/Library/Application Support/com.tabtasker.dictate/settings.json` (the app
data dir). It is written atomically (temp file plus rename), read once at launch, and an unknown
or broken file falls back to defaults field by field (serde `default` on every field). JSON is
camelCase. It is versioned with `version: 1`.

Commands:
- `get_settings()`
- `update_settings(patch)`: deep-merges a partial object, validates, saves, applies, and emits
  `dictate-settings` with the full settings to every window.

Applying means calling native `dictate_apply_settings(json)` for what the native side uses, and
telling Rust modules.

```ts
type Settings = {
  version: 1;
  general: {
    menuBarIcon: boolean;          // default true
    showInDock: boolean;           // an icon in the Dock as well, which opens Settings; default false
  };
  shortcuts: {
    dictate: 'fn' | 'rightCommand' | 'rightOption' | 'rightControl' | 'rightShift';  // held to talk; default 'fn'
    handsFree: boolean;            // double-tap the dictate key to keep listening; default true
    command: 'control' | 'option' | 'command' | 'shift' | 'off';  // with the dictate key: talk to Claude; default 'control'
    note: Chord | null;            // a global chord to start or stop a note; default null
    meeting: Chord | null;         // default null
    pasteLast: Chord | null;
    writeNote: Chord | null;      // a new note in the window, to type into
    sticky: Chord | null;         // a new sticky on the screen
    ask: Chord | null;            // a typed question for Claude       // type the last transcript again; default null
  };
  dictation: {
    language: string;              // 'auto' or a Whisper code ('en', 'tr', …); default 'auto'
    translateToEnglish: boolean;   // Whisper's translate task; default false
    liveTyping: boolean;           // words appear as you speak, else all at once on release; default true
    removeFillers: boolean;        // um, uh, er; default true
    sounds: boolean;               // a start and a stop sound; default true
    soundVolume: number;           // 0 to 1, for both; default 0.3
    startSound: string;            // one of the Mac's sounds in /System/Library/Sounds; default 'Tink'
    stopSound: string;             // default 'Pop'
    model: 'turbo' | 'small';      // large-v3 Turbo (best) or small (faster, smaller); default 'turbo'
  };
  vocabulary: {
    words: string[];               // ≤ 500, each ≤ 64 chars: names and terms Whisper should spell right
    replacements: { from: string; to: string }[];  // ≤ 500: "my email" → address; whole words, case-insensitive
    learn: boolean;                // suggest words from your own corrections; default true
    suggestions: string[];         // waiting for a yes in Settings
  };
  apps: {
    styles: { bundleId: string; name: string; style: Style; polish: boolean; send?: boolean | null }[];  // send: Return after the words; null is the app's default (on in chat apps)
    defaultStyle: Style;           // default 'default'
  };                               // Style = 'default' | 'casual' | 'formal' | 'code' | 'raw'
  notes: {
    folder: string | null;         // null = ~/Documents/TabTasker Dictate
    fileName: string;              // template, default '{date} {title}'; tokens {date} {time} {title}
    frontmatter: boolean;          // YAML front matter (created, tags, source); default true
    dailyNote: boolean;            // append to {date}.md instead of a new file; default false
    tags: string[];                // added to front matter; default []
    claudeTitle: boolean;          // Claude names the note (when connected); default true
    claudeActions: boolean;        // Claude adds action items (when connected); default false
  };
  meetings: {
    folder: string | null;         // null = <notes folder>/Meetings
    systemAudio: boolean;          // record other people too (macOS 14.2+); default true
    summarize: boolean;            // Claude summary, decisions, action items (when connected); default true
    you: string; others: string;   // speaker labels; default 'You', 'Others'
  };
  claude: {
    enabled: boolean;              // default false; true only once the way to Claude is tested (a key, or Claude Code signed in)
    via: 'api' | 'claudeCode' | 'local'; // Anthropic's API with the person's key, `claude -p` on this Mac with their account, or a model on this Mac behind Ollama's API; default 'api'
    model: 'claude-haiku-5-5' | 'claude-sonnet-5-5' | 'claude-opus-5-5';  // default 'claude-haiku-5-5'
    effort: 'low' | 'medium' | 'high'; // how long Claude may think on every request; default 'medium'
    commands: boolean;             // the command shortcut talks to Claude; default true
    claudeCode: string | null;     // path of the claude CLI when found or chosen; default null
    localEndpoint: string;         // where Ollama (or LM Studio) listens; default 'http://localhost:11434'
    localModel: string;            // the model's name there; default 'llama3.2'
  };
  agents: {
    mcp: boolean;                  // the local MCP server answers; default true
    shareHistory: boolean;         // agents can read recent dictations; default false
    shareNotes: boolean;           // default true
    shareMeetings: boolean;        // default true
    allowWrite: boolean;           // agents can create and append notes; default false
  };
  history: { keep: 'off' | 'day' | 'week' | 'month' | 'forever' };  // the words themselves; default 'week'
  appearance: {
    theme: 'system' | 'light' | 'dark';   // default 'system'
    edge: 'bottom' | 'left' | 'right';    // default 'bottom' (migrated from localStorage)
    size: 'small' | 'medium' | 'large';   // the dots and orb; default 'medium'
    idle: 'dots' | 'hidden';              // what shows when nothing happens; default 'dots'
    hint: boolean;
    margin: number;                // the dots' distance from the screen's edge, 0 to 120 pt, 0 touching the edge; default 8
    avoidDock: boolean;            // the overlay stops at the Dock and the menu bar; a Dock that hides itself is watched (dictate.m watchDock: the pointer at its edge, and its accessibility tree when allowed) and the dots step aside by its strip only while it is out (`dictate-dock`); default true
  };
};
type Chord = { keyCode: number; modifiers: number; label: string };  // NSEvent modifier mask bits; label like "⌥⌘N"
```

Validation clamps lengths and rejects unknown enum values (keeping the old value). Secrets are never
in this file: the Anthropic key lives only in the Keychain.

## 5. Cross-feature contracts

The foundation implements every contract below, as a stub where a feature fills it in later, so each
feature builds alone.

### 5.1 C boundary (dictate.m ↔ Rust)

| Function | Direction | Foundation | Filled by |
| --- | --- | --- | --- |
| `void dictate_apply_settings(const char *json)` | Rust → native | stores the parsed dictionary; the existing behaviour is kept | input, design |
| `void dictate_hold_begin(const char *request, const char *mode, const char *bundle_id)` | native → Rust; `mode` is `dictate`, `note`, `command` or `handsfree` | called from `begin`; Rust keeps it in `context.rs` | everyone reads it |
| `void dictate_type_text(const char *text)` | Rust → native, main thread | types into the focused field with the existing `TTVoiceType` (needs Accessibility; otherwise an error to the overlay) | claude, stats |
| `bool dictate_command(const char *request, const char *instruction, const char *selection, const char *bundle_id)` | native → Rust | returns false and the overlay shows "Connect Claude in Settings to use commands" | claude (Rust), input (native call) |
| `void dictate_command_result(const char *request, const char *text, const char *action)` | Rust → native; `action` is `type` or `show` | `type` types it; `show` does nothing natively | input |
| `bool dictate_meeting(const char *action)` | Rust → native; `action` is `start` or `stop` | returns false | meetings |

### 5.2 Rust modules

- `context::HoldContext { request, mode, bundle_id, app_name, started }`, with
  `context::get(request)` and `context::forget(request)`.
- `text::finish(raw: &str, ctx: &HoldContext, live: bool) -> String`. The foundation's version is the
  identity. It runs on every draft and final result in dictate and handsfree modes before they reach
  native, and must keep the existing words in the same order (drafts retype by prefix).
- `ai::polish(text: &str, ctx: &HoldContext) -> Option<String>`. This is blocking, has a 6 s budget,
  and the foundation's version returns `None`. It runs on the final result only, when the app's
  style has `polish` set and Claude is enabled; otherwise the raw text stands.
- `ai::summarize(kind: ai::Kind, text: &str) -> Option<String>` returns Markdown. Kind is `Meeting`
  or `Note`. The foundation's version returns `None`.
- `ai::title(text: &str) -> Option<String>`, foundation `None`.
- `history::record(entry: history::Entry)` takes `{ at_ms, mode, bundle_id, app_name, words, seconds, text }`.
  It is called on every final dictation, command and note. The foundation's version is a no-op.
- `notes::save_markdown(kind: notes::Kind, title, body, stamp, extra_front_matter) -> Result<PathBuf, String>`,
  where kind is `Note` or `Meeting`. `notes::recent(n) -> Vec<NoteRef>` and `notes::notes_dir()`
  use the settings.
- `speech::transcribe_piece(pcm: &[f32], opts: speech::PieceOptions) -> Result<Vec<speech::Segment>, String>`
  is blocking, locks the engine, and returns segments with start and end in samples. It is for
  meetings and takes `language: Option<String>`, `prompt: Option<String>`, `translate: bool` and
  `cancel: Option<Arc<AtomicBool>>`. Dictation comes first: a release waiting for the engine, Pause,
  Quit or `cancel` stops the piece with `speech::INTERRUPTED`, and the caller tries it again.

### 5.3 Events to pages

| Event | Payload | Emitted by |
| --- | --- | --- |
| `dictate-settings` | full Settings | settings.rs |
| `dictate-command` | `{ request, phase: 'thinking' \| 'answer' \| 'error', text?, instruction? }` | ai.rs → overlay CommandCard |
| `dictate-meeting` | `{ state: 'recording' \| 'saving' \| 'saved' \| 'error', since?, path?, message? }` | meeting.rs → MeetingPill |
| `dictate-hands-free` | `{ locked: boolean }` | native → HandsFree |
| `dictate-history` | `{ entry }` | history.rs → History page |

Existing events stay as they are.

### 5.4 The browser mock (foundation)

When `window.__TAURI__` is missing, `bridge.ts` serves an in-memory mock:
- `get_settings` and `update_settings` keep a real Settings object and emit `dictate-settings`;
- `status` returns a sample.

Each feature registers mock handlers for its own commands in `src/mock/<feature>.ts`, imported by
`src/mock/index.ts`. Every settings page then works fully in a browser at
`http://localhost:<port>/settings.html#<route>` with `?theme=light|dark` to force a theme. The
overlay keeps `?preview=<state>`.

## 6. Design system (foundation sets it; everyone uses it; design polishes)

Dictate follows TabTasker Business (`tabtasker-business-app/apps/web/src/styles/tailwind.css` and
`raised-surface.css`, documented at business.tabtasker.com/design). Business is upstream: when it
changes a token, sync it here, never the other way. The tokens are in `src/ui/tokens.css`.

- **Type.** Source Sans 3 for everything, Stack Sans Headline for display (the About name, setup
  headings, the note title, big figures). Both are bundled in `public/fonts` under the SIL OFL.
- **Surfaces.** A graphite ramp, no borders. Dark: frame #171717, rail panel #1E1E1E, page #101010,
  row #242424, muted #292929. Light: frame #F4F4F4, rail panel #FAFAFA, page #F7F7F7, row #FFFFFF,
  muted #EBEBEB; the window's shell, as Business's light workspace, uses the muted grey as its frame
  and the row white as its page. Ink #EDEDED / #202020, secondary ink #A8A8A8 / #595959.
- **Depth.** Raised lifts a row or control off the page, well presses it in (a focused field, the
  chosen page in the rail), control is a filled button with a lit rim, float is a card over other
  things. Light hairlines are inset and faint: the UI is layered, not drawn.
- **Accent.** Business blue, #3B82F6 dark and #2563EB light: primary buttons, toggles, progress, the
  chosen key, links. Selection elsewhere reads as depth, not hue. Focus is a 2 px ring in ink at 60%,
  2 px out.
- **Shell.** The window is Business's Mac workspace frame (section 5.5): the frame colour behind
  everything, a 40 px title bar with tabs, a 56 px icon spine on the frame, the column as a raised leaf
  rounded on its left, and the page as a raised pane with a 20 px radius over the column's inner
  24 px; a 12 px gutter right and bottom, none on the left.
- **Layout.** A section is a soft panel (18 px radius) holding raised rows (12 px) with 6 px gaps.
  Page title 20/600 with its glyph, row title 14/500, detail 12.5, section title 14/600.
- **Motion.** 150 and 250 ms on cubic-bezier(.22, 1, .36, 1); cards spring in; all off under reduced
  motion.

Components in `src/ui/`:
- `Button` (primary, which is accent on accent text; secondary; quiet; danger), `Toggle`,
  `Segmented`, `Select`, `TextField`, `Slider`.
- `Kbd`, `KeyRecorder` (records a chord, shows ⌃⌥⇧⌘ glyphs, Escape cancels, Delete clears).
- `Tile`, `TileGroup`, `Section`, `PageHeader`, `EmptyState`, `ProgressBar`, `Toast`.
- `Icon`: a monochrome line set at 1.5 stroke on a 20 grid, used in the sidebar and menus.

Every page is built from these.

## 7. Features and acceptance

### 7.1 Foundation
- Covers sections 3 to 6.
- Splits `Overlay.tsx` without changing behaviour; the existing `?preview=` states look the same
  except that colour becomes the monochrome accent.
- Moves the overlay's edge from localStorage to settings, with a one-time migration.
- Adds "Settings…" to the tray and the right-click menu.
- Builds the app menu.
- Tests: settings defaults, a partial patch and invalid values, the atomic save round-trip, and the
  note path tests (kept).
- Leaves `cargo test` warm in `src-tauri/target/debug`.

### 7.2 Input (dictate.m key handling, Shortcuts page, HandsFree.tsx)

- **The dictate key.** It is any of the five keys, not only fn:
  - Right-side modifiers are told apart by key code: right ⌘ 54, right ⌥ 61, right ⌃ 62,
    right ⇧ 60, fn 63.
  - Pressing another key while it is held is still a shortcut, so the hold is cancelled as today.
  - Setup's fn test follows the chosen key.
- **Hands-free.**
  - A double tap of the dictate key (two presses within 0.35 s, each under 0.25 s) locks listening.
  - A single tap or Escape stops: a tap sends, Escape cancels.
  - It emits `dictate-hands-free`.
  - A locked session runs up to 10 minutes. The engine side of long audio belongs to speech.
- **Command.** Holding the dictate key with the command modifier records in `command` mode. On
  release it calls `dictate_command` with the transcript, the field's selected text (AX) and the
  front app. `dictate_command_result` with `type` types the result over the selection, or at the
  caret.
- **Chords.**
  - The note, meeting and paste-last chords are global, through the existing monitors (they need
    Accessibility).
  - When the overlay is key the local monitor handles them.
  - A chord already taken by the system is refused with a reason in the recorder.
- **Sounds.** A start and a stop sound when `dictation.sounds` is on: any two of the Mac's own sounds, at
  `dictation.soundVolume`, chosen by ear on the Dictation page (a Play button previews each).
- **Shortcuts page.** The key picker shows a picture of the chosen key, plus the hands-free toggle,
  the command modifier, the three chord recorders and a live "press it now" tester.
- **Tests.** Extract the tap and double-tap state machine and the chord matching into small C
  functions with a Rust or C unit test, so they are testable without events.

### 7.3 Speech (speech.rs, text.rs, Dictation, Vocabulary and App styles pages)

- **Language.** `language` either pins the language (no detection pass) or keeps today's
  detection when it is `auto`.
- **Translate.** `translateToEnglish` sets Whisper's translate.
- **Vocabulary.** The words reach Whisper as `initial_prompt`, a comma list kept under 200 tokens,
  most recent first. Replacements run in `text::finish`: whole words, case-insensitive, keeping
  punctuation.
- **Fillers.** Removed in `text::finish` (um, uh, er, ah, hmm, standalone "like" is NOT removed),
  without breaking capitalization or spacing.
- **Styles.** Local and deterministic, so they are safe for live drafts:
  - `casual`: no trailing period on a single sentence, keeps case;
  - `formal`: a capital first letter and a final period;
  - `code`: spoken symbols and casing commands ("camel case user name" → `userName`, "snake case",
    "kebab case", "all caps", "open paren", "dot", "new line" …) and no auto-capital;
  - `raw`: Whisper as is.

  The default app styles ship with sensible entries: Terminal, iTerm, Ghostty, Warp, VS Code,
  Cursor, Xcode and Zed are code; Messages, Slack, WhatsApp and Discord are casual; Mail and
  Outlook are formal. The App styles page lists running and recent apps (icon, name) to add.
- **Learn.** After a dictation, if the person edits a dictated word within 30 s in the same field
  (AX value diff limited to the dictated range), the corrected word becomes a suggestion and
  `dictate-learned` fires. Nothing is added without a yes.
- **Model.** Small is an option with its official URL and a verified SHA-256 from the ggml repo.
  Switching downloads it with progress and keeps the other.
- **Long audio.** Up to 10 minutes for hands-free: drafts work on the uncommitted tail like notes do,
  and the final result is the full text.
- **`transcribe_piece`** for meetings.
- **Tests** for every text rule, including Unicode and Turkish casing (İ/ı), and for replacements
  at punctuation.

### 7.4 Notes (notes.rs, panels.m, Notes page)

- **Folder.** A choose-folder button opens an NSOpenPanel. It detects an Obsidian vault (a
  `.obsidian` folder in the chosen folder or a parent) and says so.
- **File names.**
  - The template supports `{date}` (YYYY-MM-DD), `{time}` (HH.mm) and `{title}`.
  - Names are sanitized.
  - A name is never overwritten.
- **Daily note** appends `## HH:mm title` sections to `{date}.md`.
- **Front matter** carries `created`, `tags` and `source: TabTasker Dictate`.
- **Claude.** With Claude connected, Claude names the note and can add an "Action items" section.
- **Recent notes** feed the tray's Recent Notes submenu.
- **Notes page.** A live preview of the file name and the front matter.
- **The editor.** `note_read` splits a file into front matter, `# title` and body; `note_write` writes
  it back the same way (a `title:` in the front matter follows the title); `note_new` makes a file with
  whatever words there are, none included (the window's plus, Write a note); `note_delete` moves a file
  to the Trash; `note_attach` keeps a pasted or dropped picture in `attachments/<note>/` beside the note
  and answers its relative path, shown through the asset protocol (`$HOME/**`). A spoken note is saved
  the moment it ends (the model names it, or its first words do) and opened in the window; there is no
  review card. The editor is TipTap with Business's bar (`src/editor/`): headings, lists, to-dos, quotes,
  code blocks with highlight.js colours, tables (a 3 × 3 from "/" or the bar, rows and columns from the
  bar while inside one), pictures, links, highlights; "/" for the blocks; a bar over a selection; a drag
  handle per block; Markdown in and out through `@tiptap/markdown`. Stickies write in the same editor,
  compact. A sticky can also be said: "sticky: call Thomas" while dictating makes one instead of typing
  (`text::sticky_words`).
- **Tests** for the template, daily appends, front matter, vault detection and the editor's split.

### 7.5 Meetings (meeting_audio.m, meeting.rs, MeetingPill.tsx, Meetings page)

- **Starting.** From the pill on the dots (a meeting button beside the note, with a red dot while
  recording), the Meetings place in the window, the dots' right-click menu, the menu bar, Settings ›
  Notes & meetings or the chord.
- **Audio.** The microphone (AVAudioEngine with voice processing on, so the speakers' echo is
  cancelled) plus system audio through a Core Audio process tap (macOS 14.2+:
  `CATapDescription` global tap, an aggregate device, an IOProc, and resampling to 16 kHz mono).
  - Add `NSAudioCaptureUsageDescription` to Info.plist.
  - Below 14.2, or without permission, it records the mic only and says so.
- **Transcription.**
  - Each stream is cut at pauses into pieces of 25 s or less and run through `transcribe_piece`.
  - Segments are merged by time into `**You** 00:01:23 text` lines.
  - **Speakers** (`speakers.rs`, Meetings › Tell speakers apart, default on). After Stop, each stream's
    whole recording goes through sherpa-onnx's diarization on this Mac: pyannote segmentation-3.0 finds
    where voices start and stop, NeMo TitaNet small gives each stretch a voiceprint, and clustering groups
    them. Each transcribed line takes the voice that covered most of it. The microphone's main voice (by
    time spoken) keeps "Your name"; every other voice, in the room or on the call, is numbered in order of
    first appearance, Person 1, Person 2…; a stream whose voices couldn't be told apart keeps its own
    label. The two models (47 MB) download beside the voice models when a meeting first starts with the
    switch on; a meeting that ends before they arrive is labelled by stream. The saved file is Markdown,
    so names are renamed in the editor.
  - Pieces are transcribed while the meeting runs, so the end is quick.
- **Stopping.** Stop saves a Markdown file in the meetings folder:
  - title (Claude, or "Meeting {date} {time}");
  - Summary, Decisions and Action items (Claude, when on);
  - the transcript.
- **The pill.** It shows a recording dot in the accent, the elapsed time and Stop, near the
  dots.
- **Safety.** It never loses audio. A crash-safe spool file holds untranscribed audio until the
  meeting is saved.
- **Tests** for the merge, the timestamp format and the file assembly.

### 7.6 Claude (ai.rs, keychain.m, Claude page, CommandCard.tsx)

Load the `claude-api` skill first and follow it.

- **Key.**
  - Pasted once, saved in the Keychain (service `com.tabtasker.dictate`, account `anthropic`).
  - Tested with a 1-token request before `enabled` flips on.
  - Shown only as "Saved" with Remove.
- **Model.** The model picker defaults to Haiku 5.5 for speed.
- **Calls.** Direct HTTPS to the Messages API with reqwest (rustls, ring), with timeouts. Errors
  are mapped to plain sentences (bad key, rate limit, offline).
- **Polish** per app style, with a 6 s budget and the raw text on any failure.
- **Commands.**
  - With a selection, the instruction transforms it and the result is typed over it.
  - Without one, a question gets an answer card in the overlay with Insert, Copy and Close.
  - "Write …" requests type at the caret.
- **Summaries and titles** for meetings and notes.
- **Claude Code.** Finds the `claude` CLI: `which` in a login shell, then `~/.local/bin`,
  `/opt/homebrew/bin` and `/usr/local/bin`. Everything runs headless (`claude -p`); nothing ever opens
  Terminal, Claude Code or Claude Desktop in front of the person. Connecting through Claude Code also
  adds this app's MCP server to Claude Code quietly (`agents_add`), so it can read the notes.
- **A local model** (`Route::Local`): Ollama's `/api/chat` at `localEndpoint` with `localModel`, one
  turn, no streaming, a JSON schema as `format` when a request has one. Connect tests it with a one-word
  request (`claude_connect_local`); the errors say when Ollama isn't running or hasn't the model.
- **Agents page.** Connect through Claude Code, a key or a local model (one disconnect for all);
  the model and the effort (low, medium or high, applied to every request; the probes stay at low); what the model sees (text only, never audio); the Claude Code path; and what Claude Code
  and Claude Desktop may read (folded into the same page).
- **Tests** with canned HTTP responses: request shape, error mapping, timeouts and the
  prompt-injection-safe framing of user text.

### 7.7 Agents (mcp.rs, the Reading your notes part of Claude & AI)

- **The server.** `tabtasker-dictate --mcp` (main.rs checks the argument before starting Tauri)
  speaks MCP over stdio: JSON-RPC 2.0 with initialize, tools/list and tools/call, at protocol
  version 2025-06-18.
- **Tools**, each gated by its `agents.*` setting:
  - `list_notes`, `read_note`, `search_notes`;
  - `list_meetings`, `read_meeting`;
  - `recent_dictations` (history, off by default);
  - `create_note`, `append_to_note` (only with allowWrite).

  Reads are confined to the notes and meetings folders (canonicalized, no symlink escape).
- **Reading your notes.**
  - Claude Code is added when Claude connects through it; "Add to Claude Code" runs
    `claude mcp add --scope user tabtasker-dictate -- <exe> --mcp` by hand too.
  - "Add to Claude Desktop" merges `mcpServers` into Claude Desktop's config with a backup and
    never clobbers other servers.
  - The page shows status: installed or not, and the last call.
- **Tests** run the server in a temp HOME over a pipe: the handshake, every tool, gating, path
  escape attempts and malformed input.

### 7.9 Setup (onboarding/, General page, Setup.tsx)

The first launch opens the Settings window on `#setup`, a full-window guided flow:

2. **Microphone.**
3. **Accessibility,** with live status.
4. **Choose your key,** with the keyboard picture that lights while it is held.
5. **Speech model:** language and download with progress.
6. **Try it:** a practice field in the window. Hold the key and speak, and it types there. The step
   passes when words arrive.
7. **Extras,** each optional: connect Claude, meetings permission, notes folder.
8. **Done:** the ways cheat sheet.

- Steps show live state from `status` (polled while open) and never dead-end: every permission step
  says exactly what to click in System Settings, with an Open button.
- **Sending.** With `send` on for the app (chat apps by default: Slack, Messages, WhatsApp, Teams, Telegram,
  Discord, Signal), Return follows the words once they are all typed where they went. Saying "send", "send
  it" or "send message" at the end sends that one message in any app; the words are left out of the text.
- **Writing a note.** Write a note (the menu, a shortcut) and the plus in the window's Notes make a new
  file at once and open it in the editor with the keyboard in it; typing and talking both go in, and it
  saves as you go. There is no card to confirm.

  dictations that Claude & AI shares; what the tools return is told to be material, not instructions, and
